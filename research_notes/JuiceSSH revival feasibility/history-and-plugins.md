# JuiceSSH history, discontinuation evidence, plugins, SDK and historical Pro specification

Research date: 2026-10-18. Read-only web/GitHub research; no APKs downloaded, installed or executed. Availability means the indicated page, repository, tree or release metadata was retrieved—not that an APK was authenticated, a project built, or a service tested. This is a bounded discovery inventory, not a claim that every unpublished/private plugin or fork has been found.

## 1. How did JuiceSSH develop, and what actually supports discontinuation?

### Takeaway

JuiceSSH has a documented history from December 2012, a public plugin ecosystem from 2013, and a last observed main-app version of 3.2.2 in 2021. Evidence supports prolonged release inactivity, later Play removal and reported entitlement failures; it does **not** establish that Sonelli Ltd shut down or that its rights became available. [AppBrain](https://www.appbrain.com/app/juicessh-ssh-client/com.sonelli.juicessh), [release listing](https://www.apkmirror.com/apk/sonelli-ltd/juicessh-ssh-client/juicessh-ssh-client-3-2-2-release/), [Sonelli repositories](https://api.github.com/orgs/Sonelli/repos?per_page=100).

- **Entitlement/backend evidence is weaker than removal evidence:** AppBrain republishes user complaints about paid features stopping, purchases no longer recognized and unanswered support. A community recovery module explicitly describes the original verification path as unavailable. These are user/third-party reports, not independently reproduced failures or an authoritative incident timeline. [User reports](https://www.appbrain.com/app/juicessh-ssh-client/com.sonelli.juicessh), [module author's account](https://github.com/li-yifei/JuiceSSHOfflineProFix).

They do not show a new main application release and can reflect branch/fork activity. [Organization metadata](https://api.github.com/orgs/Sonelli/repos?per_page=100).

### Inferences

- “Apparently unmaintained and no longer publicly listed on Google Play” is defensible. “Officially discontinued on date X,” “all services permanently shut down,” and “company dissolved” exceed the collected evidence. [App history](https://www.appbrain.com/app/juicessh-ssh-client/com.sonelli.juicessh), [Play observation](https://play.google.com/store/apps/details?id=com.sonelli.juicessh&hl=en).
- Plugin/SDK recovery is better supported than recovery of the complete main client: the public organization inventory exposes plugin and component repositories but no clearly identified complete original JuiceSSH app source. [Inventory](https://api.github.com/orgs/Sonelli/repos?per_page=100).

### Gaps

- No authoritative discontinuation announcement, corporate-status filing, rights transfer, main-client source release, signing-key availability or maintainership handover was established.
- No authenticated CloudSync, TeamShare, purchase-restoration or EC2Link transaction was tested. A website transport error does not prove that all API endpoints are dead.
- Exact 2012 launch day and a complete version-by-version 2012–2021 changelog remain unverified. Wayback's CDX identifies historical paths, but many page captures share the same application-shell digest; a 200 response is not proof the requested article was preserved. Useful substantive captures are `/partials/about` and `/partials/features`. [CDX query](https://web.archive.org/cdx/search/cdx?url=juicessh.com/*&output=json&filter=statuscode:200&collapse=urlkey&filter=mimetype:text/html).

## 2. Which plugins, extensions, SDK assets and public repositories can be recovered?

### Takeaway

Three functional official plugins plus the example and SDK have public Apache-2.0 repositories. Tasker is a verified historical product with a mirror listing, but no source repository was found; community FreeNAS and Openpyn plugins have publisher-repository APK asset entries. Source or release-metadata availability must not be conflated with modern Android compatibility. ## 3. What exactly did historical Pro include?

### Takeaway

The best recovered primary specification is Sonelli's own English store listing in its translations repository, supplemented by the archived first-party feature page and the 3.2.2 listing. Pro was described as an optional in-app purchase with eight main feature categories; ordinary terminal access, Mosh, Telnet, identities and community plugins were listed separately. [Official store text](https://github.com/Sonelli/juicessh-translations/blob/master/en_US/STORE-LISTING), [archived feature page](https://web.archive.org/web/20240318221739id_/https://juicessh.com/partials/features), [3.2.2 text](https://www.apkmirror.com/apk/sonelli-ltd/juicessh-ssh-client/juicessh-ssh-client-3-2-2-release/).

### Inferences

- A local-feature revival and a cloud-feature revival are substantially different scopes: forwarding, widgets, snippets and UI locking can be specified from historical behavior, whereas CloudSync/TeamShare and possibly entitlement restoration require additional service/protocol evidence. Existing backup clients document part of the cloud path, not a replacement server. [Pro specification](https://github.com/Sonelli/juicessh-translations/blob/master/en_US/STORE-LISTING), [gojuice](https://github.com/Sonelli/gojuice), [pyjuice limitations](https://github.com/markus-li/pyjuice).
- A module that changes local Pro checks does not itself recreate CloudSync, TeamShare or EC2Link services. Its author's scope is offline entitlement usability, not proof of complete Pro recovery. [Module description](https://github.com/li-yifei/JuiceSSHOfflineProFix).

### Gaps

- Historical Pro price by market/date, promotions, exact purchase SKU, license portability and contractual “lifetime” terms were not established from primary terms. User reviews mentioning lifetime purchases are not sufficient evidence.
- No recovered specification establishes SFTP/SCP file browsing as a shipped Pro feature. SDK SFTP interfaces warrant further investigation but do not fill this gap.
- Encryption claims are historical marketing/specification statements, not a cryptographic audit. KDF, authentication, metadata exposure, team-key handling and current server data retention require separate investigation.
