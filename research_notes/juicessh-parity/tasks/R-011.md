## Behavior contract and LimeSSH mapping

**Preconditions**: SSH session active; scrollback contains ≥ 1 row.
**Action**: User drags vertically upward on the terminal Canvas.
**State changes**: `scrollOffset` decrements (negative = scrolled back into history); Canvas renders scrollback rows at the top of the viewport, replacing live rows that scrolled off. A progress indicator shows position within the scrollback buffer. New output from the server does NOT auto-return to live view while user is scrolling; returning to `scrollOffset == 0` re-enables auto-live.
**Alternative action**: New output arrives while user is in scrollback — no auto-scroll-jump (JuiceSSH behavior: new content causes `mScrollCounter` increment; EmulatorView draws at current `mTopRow` without forcing return; user drags back).
**Error/recovery**: `scrollOffset` clamped to `[-scrollback.size, 0]`; 0 = live.
**Alternate screen**: do not push rows into scrollback when `useAltScreen`; existing code already handles this.

## Review and implementation handoff

- Evidence sufficient for implementation: all key fields and methods are identified.
- Proposed change: (1) add `fun getRow(relRow: Int): Array<TermCell>?` to `TerminalEmulator.kt`; (2) add `scrollOffset: Int` state + `detectVerticalDragGestures` + scroll indicator to `TerminalScreen.kt`.
- Thread safety: `scrollback` is accessed on main thread (via snapshot count) and IO thread (written by `scrollUp`). `getRow` needs `@Synchronized` annotation.
- Risk: large scrollback snapshots are not copied on every recompose — only offset changes trigger render, no new allocation.
- Validation: run `./gradlew testDebugUnitTest` (add tests for `getRow` boundary conditions).
