# R-017 — Known-hosts management UI (S-01)

## Scope and exit criteria

- **Question**: What data layer exists for managing stored SSH host fingerprints, and what minimal UI exposes viewing and deletion?
- **Current LimeSSH**: `KnownHostDao`, `ConnectionRepository.observeKnownHosts()`, `DatabaseHostKeyVerifier`.

## Findings

All data layer present: `KnownHostDao.observeAll()` / `deleteByHostAndPort()` / `upsert()` / `findByHostAndPort()`. `ConnectionRepository.observeKnownHosts()` returns `Flow<List<KnownHost>>`. No UI screen existed; `observeKnownHosts()` was never called from any UI file.

## Implementation

- `ConnectionRepository.kt`: Added `suspend fun deleteKnownHost(host: KnownHost)` delegating to `dao.deleteByHostAndPort(host.hostname, host.port)`.
- `KnownHostsScreen.kt` (new): `LazyColumn` of `ListItem` rows (host:port, key type, truncated public key, delete icon); confirm-delete `AlertDialog`. Empty state message when list is empty.
- `AppNavigation.kt`: Added `Routes.KNOWN_HOSTS = "known_hosts"` and `composable` destination.
- `SettingsScreen.kt`: Added `onOpenKnownHosts: () -> Unit` param; new "Known hosts" `SettingsItem` under Security section.
- Route in `AppNavigation.kt`: `SettingsScreen(onOpenKnownHosts = { navController.navigate(Routes.KNOWN_HOSTS) })`.
