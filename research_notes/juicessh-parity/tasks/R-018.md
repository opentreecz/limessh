# R-018 — Auto-reconnect, keepalive, network-change handling (C-04)

## Scope and exit criteria

- **Question**: What SSH keepalive mechanism does SSHJ provide, and what minimal change gives LimeSSH SSH-level keepalive and a visible "Connection lost / Retry" path when the channel drops?
- **Boundary**: Full auto-reconnect loop and `NetworkCallback` are deferred (complex; needs separate planning).

## Findings

SSHJ 0.40.0 provides `net.schmizz.keepalive.KeepAliveProvider` with two strategies:
- `HEARTBEAT`: sends `SSH_MSG_IGNORE`; server not required to respond; keeps TCP alive only.
- `KEEP_ALIVE` (KeepAliveRunner): sends `SSH_MSG_GLOBAL_REQUEST`; expects server reply; closes transport after N missed replies. Default max-alive-count = 3.

`SSHClient()` no-arg ctor uses no custom provider (keepalive interval = 0 = disabled). Must provide a custom `DefaultConfig` and then call `client.connection.keepAlive.setKeepAliveInterval(n)`.

Existing `SshEngine.connect()` sets `client.connectTimeout = 15_000` and `client.timeout = 30_000` but no keepalive. A silently dead TCP connection can block `shell.channel.join()` indefinitely.

## Implementation

### `SshEngine.kt`
- Changed `SSHClient()` construction to use `DefaultConfig` with `setKeepAliveProvider(KeepAliveProvider.KEEP_ALIVE)`.
- Added `fun enableKeepAlive(intervalSeconds: Int = 60)` — calls `client.connection.keepAlive.setKeepAliveInterval(intervalSeconds)` wrapped in `runCatching`.

### `SessionManager.kt`
- Calls `engine.enableKeepAlive(60)` immediately after `engine.connect()`.
- Added `val disconnected: MutableStateFlow<Boolean>` to `SshSession` (defaults `false`).
- Lifecycle coroutine sets `session.disconnected.value = true` in the `finally` block, before calling `disconnect()`.

### `TerminalScreen.kt`
- `LaunchedEffect(currentSession)` collects `session.disconnected`. When `true` and no prior error: sets `connectionError = "Connection lost…"` so the existing "Retry" button becomes visible.

## Deferred
- Full auto-reconnect loop with exponential backoff (needs separate R-018b task).
- `ConnectivityManager.NetworkCallback` for network-change-triggered reconnect (needs Android service-layer changes).
