| `Lcom/sonelli/pi0;->j(Landroid/content/Context;Lcom/sonelli/pi0$p;)V` | Account/cache/refresh path → local user callback | `hook_api_gate` |

The duration is not a timestamp or persisted expiry. Without the last replacement,
original `pi0.j` can still refresh after an hour or after loading a local user.
`User.H` concerns app-account signatures, not SSH host-key verification.

Startup matches exactly `com.sonelli.juicessh`; other packages do nothing. Config
loads once per package-load callback: four booleans default true, years 10 clamped
1–100. It attempts world-readable preference access/reload, ignores that Boolean
success result, and catches loading errors to use defaults. Each hook registration
has its own catch/log path; partial installation is possible.

For `pi0.j`, null callback returns immediately. Otherwise it tries `User.A(context)`;
null/non-Context input, missing user or caught lookup error yields a newly constructed
User. DEX confirms a catch-all over bytes **[0x18,0x50)** with handler **0x52**,
omitted by JADX. User construction and callback invocation are outside that catch.
It resolves public `b` using the user's exact runtime class and invokes synchronously;
construction/reflection/callback errors can escape. Xposed error handling is untested.
A blank User recovers no account/session/purchases. Only this method's original
refresh path is omitted; other app networking is not ruled out.
