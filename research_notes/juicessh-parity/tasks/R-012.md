# R-012 — Text selection, copy, paste, transcript save (TM-02)

## Scope and exit criteria

- **Question**: What is the minimal correct design for text selection (long-press to start, drag to extend), copy to clipboard, paste from clipboard, and "save/share transcript" in LimeSSH's Compose terminal Canvas, consistent with JuiceSSH's observed behavior?
- **Allowed legacy**: `EmulatorView.java` (mIsSelectingText, onTouchEventWhileSelectingText, getSelectedText), `TerminalEmulatorActivity.java` (context menu items 4/5, copyToClipboard, share intent, dialog transcript copy).
- **Current LimeSSH**: `TerminalScreen.kt`, `TerminalEmulator.kt`.
- **Excluded**: Scrollback rendering (R-011 dependency). IME accessibility (R-015).
- **Deliverable**: spec_ready card with behavior contracts; implementation dispatched separately as I-R-012.
- **Exit criteria**: all REQs have Given/When/Then; failure paths and dependencies are explicit.

## Behavior contract and LimeSSH mapping

**Copy selection flow**: long-press → selection mode active; drag adjusts end cell; "Copy" taps → clipboard; exit selection mode on copy or tap-outside.
**Paste flow**: IME paste action or dedicated "Paste" button → reads clipboard text → sends bytes to session (no bracketed paste wrapping, to match legacy).
**Transcript flow**: "Share transcript" menu item → `getTranscriptText()` → `Intent.ACTION_SEND` with `text/plain`.
