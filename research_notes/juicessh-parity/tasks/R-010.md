## Legacy Sequence Response Table

| Sequence | Name | Legacy Action / Bytes Sent | Format / Note |
|---|---|---|---|
| `ESC [ c` or `ESC [ 0 c` | Primary Device Attributes (DA) | `\u001b[?1;2c` (`1B 5B 3F 31 3B 32 63`) | VT100 with Advanced Video Option |
| `ESC Z` | DEC Private Terminal ID | `\u001b[?1;2c` (`1B 5B 3F 31 3B 32 63`) | Deprecated VT52/VT100 sequence |
| `ESC [ 5 n` | Device Status Report (DSR) | `\u001b[0n` (`1B 5B 30 6E`) | Status OK |
| `ESC [ 6 n` | Cursor Position Report (CPR) | `\u001b[<R>;<C>R` (e.g. `\u001b[1;1R`) | 1-indexed: `cursorRow + 1`, `cursorCol + 1` |
| `ESC [ <other> n` | Other DSR variants | Ignored | No response sent |
| `ESC [ > c` | Secondary Device Attributes (DA2) | Not handled in Jackpal | Ignored (can be considered in future terminal workstream) |

## LimeSSH Architecture & Response Flow

To avoid deadlock or recursive parsing:
1. `TerminalEmulator` constructor receives an optional response callback:
   `var onOutput: ((ByteArray) -> Unit)? = null`
2. When parsing CSI `c`, ESC `Z`, or CSI `n`:
   - If `onOutput` is null, do nothing.
   - For `c` or `ESC Z`: invoke `onOutput?.invoke("\u001b[?1;2c".toByteArray(Charsets.US_ASCII))`
   - For `n` with `p1 == 5`: invoke `onOutput?.invoke("\u001b[0n".toByteArray(Charsets.US_ASCII))`
   - For `n` with `p1 == 6`: invoke `onOutput?.invoke("\u001b[${cursorRow + 1};${cursorCol + 1}R".toByteArray(Charsets.US_ASCII))`
3. In `SessionManager.kt`:
   - When creating an `SshSession`, initialize `emulator = TerminalEmulator(...)` and set:
     ```kotlin
     emulator.onOutput = { data ->
         scope.launch(Dispatchers.IO) {
             runCatching {
                 synchronized(shell.stdin) {
                     shell.stdin.write(data)
                     shell.stdin.flush()
                 }
             }
         }
     }
     ```
   - Dispatch on `Dispatchers.IO` to ensure writing responses does not block the input-parsing coroutine or introduce feedback deadlocks.
