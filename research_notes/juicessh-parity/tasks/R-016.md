# R-016 — ssh:// and quick-connect URI handling (C-01)

## Scope and exit criteria

- **Question**: How does JuiceSSH dispatch incoming `ssh://` URIs, and what minimal change routes them to a usable connection editor in LimeSSH?
- **Allowed legacy**: `ConnectionIntentParser.java` method `c(uri)` (raw URI parse path).
- **Current LimeSSH**: `MainActivity.kt:27`, `AppNavigation.kt`, `ConnectionEditScreen.kt`.

## Findings

JuiceSSH's `ConnectionIntentParser.c(uri)`:
- `uri.host` → address; `uri.port` (default 22 per scheme); `uri.userInfo` → temporary identity; optionally persists.
- LimeSSH manifest registered `ssh` scheme but `readConnectionIntent` only parsed `limessh://connection/<uuid>`.

## Implementation

- `MainActivity.kt`: Added `SshQuickConnect(address, port, user?)` data class. `readConnectionIntent` now also checks `data.scheme == "ssh"` → parses host/port/user → sets `sshQuickConnect` state.
- `AppNavigation.kt`: New `sshQuickConnect` / `onQuickConnectDismissed` params. Overlay `AlertDialog` shows host/port/user with "Edit & connect" and "Cancel". "Edit & connect" navigates to `connection/new?address=…&port=…&user=…`.
- New parameterized route `connection/new?address={address}&port={port}&user={user}` (optional args).
- `ConnectionEditorRoute.kt`: Added `prefillAddress`, `prefillPort`, `prefillUser` params; passed to `ConnectionEditScreen`.
- `ConnectionEditScreen.kt`: State variables initialize from `prefill*` when `connection == null`.
